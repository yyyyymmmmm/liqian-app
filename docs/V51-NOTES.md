# v5.1 小组件全面重做（5.1.0 / 53）

用户原话：现在的小组件太 low，看看专业的小组件都会显示什么。本版只动小组件
（外加待回页深链承接与快照一个可选字段），App 其他页面、Live Activity、
统计口径一律不动。

## 一、调研：专业小组件显示什么

来源分两类：苹果官方文档（HIG Widgets / WidgetKit）与品类通行实践
（Things、Fantastical/苹果日历、鲨鱼记账等记账类的组件形态，业界长期
稳定的通行做法，非某一家某一版的截图口径）。

**官方口径（HIG Widgets）**
- 组件的本职是 glanceable：少量、及时、相关的信息，一眼看完，不打开 App。
- 密度要「舒适」：内容稀疏会显得组件没必要存在，太密又不 glanceable；
  层级靠大数与小字的对比拉开，不靠堆字。
- 点按要深链到「对的位置」，不是 App 首页：如中尺寸股票组件点一行进
  该股页面。多个点按目标可以，但不能做成 App 式布局。
- 敏感信息（余额类）在锁屏/遮蔽场景必须打码（.privacySensitive()）。
- 交互只许 Button/Toggle（iOS 17+），其余全靠 Link/widgetURL 深链。

**通行实践（对标归纳）**
- Things（小）：今天清单的头几行＋完成进度，一眼知道「还剩什么」；
  Fantastical/日历（小）：日期大字＋下一场事件名与时间，永远只讲下一场；
  记账类（鲨鱼记账等）：组件＝本月账单概览（本月支出大数）＋快捷记账
  入口，「看数＋记一笔」是记账组件的固定双件套。
- 中尺寸通行形态：一侧英雄数、一侧 2–3 行可点列表（日历的今日日程、
  待办的今日清单都是这个骨架）。
- 大尺寸通行形态：一块迷你仪表盘——汇总数＋名单＋下一项日程＋快捷
  动作，四块信息各占一区，不留大面积空白。
- 锁屏圆形（accessoryCircular）通行形态：单一指标做成仪表（活动圆环
  式），圆心放数字；矩形就是两行摘要，第一行是结论、第二行是细节。

**结论（本版信息架构的依据）**
- 小尺寸＝一个英雄数＋一条支撑信息＋新鲜度（数据时间要诚实摆出来）。
- 中尺寸＝英雄数＋2–3 行可点列表，逐行直达对象本身。
- 大尺寸＝迷你仪表盘：汇总＋名单＋下一场＋快捷动作，四象限对齐。
- 锁屏＝单一指标仪表（圆形）或两行摘要（矩形）。
- 专业感来自五件事：层级（大数/小字对比）、真实数据密度、可点直达、
  占位与空态有尊严（骨架屏/结论式空态，不空白、不假数据）、与 App 内
  语义完全一致（同一套金额符号与颜色口径、同一个待回定义）。

## 二、现状盘点（v5.0.2 的小组件为什么显得 low）

| 组件 | 现状 | 问题 |
|---|---|---|
| 待回·小 | 英雄数是「人数」（大字）＋总额作小字＋「最多的是 X」（无金额） | 英雄数选错：用户最关心的是欠多少，不是欠几个人；第一待回人只有名没有数 |
| 待回·中 | 左名单 3 行＋右「记一笔」按钮 | 没有英雄数，左列第一行还是标题，密度低；按钮占掉近半版面 |
| 待回·大 | 名单 5 行＋本月收/送＋下一场 | 本月收/送是墨色无符号无语义色，与 v5.0.2 的 App 内口径脱节；名单给 5 行反而挤掉结构感；无记一笔 |
| 待回·锁屏圆 | 人数数字＋「待回」 | 没有仪表环，只是个数字贴在圆里 |
| 待回·锁屏矩 | 第一行「待回礼 N 人」、第二行第一人姓名＋金额 | 第一行不是结论（总额），要算一下才知道欠多少 |
| 倒计时·小/中 | 事件名＋天数大字＋日期 | 骨架基本对，差在日期无星期、无空态设计、占位是空白 |
| 全部 | placeholder(in:) 返回空条目 | 系统加载时桌面出空白版式，第一眼最 low 的就是这里 |
| 全部 | 无数据新鲜度 | 快照是几点写的用户无从判断，数字可信度打折 |
| 记一笔 | 中尺寸有真按钮（AppIntent） | 保留并推广到大尺寸；小尺寸维持整卡深链 |

好消息：底座不差——待回口径与 App 同源（pending=max(balance,0)）、人物
深链、记一笔真意图、App 写快照后 reloadAllTimelines 都已在位，本版是
版式与信息架构重做，不是推倒重来。

## 三、本版落地

**版式（PendingWidgets.swift 整份重排，kind 不变、老桌面组件原地升级）**
- 小·待回：英雄数＝待回总额（title 大字），支撑行＝「共 N 人待回」，
  下方第一待回人一行（姓名＋收向带符号金额、整行 Link 直达该人），
  底部新鲜度「今天 HH:mm 更新 / M月d日 HH:mm 更新」。整卡其余区域
  点按落待回页。
- 小·下一场（ReminderWidget 小）：事件名＋剩余天数大字＋日期带星期
  （「11月16日 星期一」），数据与首页倒计时卡同源（同一份快照的
  nextReminder 字段、天数按今天现算），不另算一套。
- 中·待回：左英雄区（待回总额＋人数＋新鲜度）＋右前三名待回人行
  （姓名＋金额，逐行 Link 直达）。记一笔按钮移出中尺寸（版面还给
  数据），大尺寸保留。
- 大·仪表盘：顶栏本月收/送两块（符号＋语义双色）→待回区（区头带
  总额＋前三名逐行直达）→下一场倒计时条（标题＋天数＋日期）→底部
  「记一笔」整宽真按钮（沿用 OpenQuickRecordIntent，非深链假按钮）。
- 锁屏·圆形：待回人数仪表——Gauge accessoryCircular，圆心人数＋
  「待回」；环形进度的口径＝**待回人数 ÷ 全部往来人数**（往来的人里
  还有几成的人情没回）。分母是本版给快照新加的可选字段 peopleCount
  （App 侧 WidgetSummaryWriter 写入，口径＝LedgerMath.people 的全部
  人数）；旧快照无此字段时降级为原来的无环数字版式，不编比例。
- 锁屏·矩形：第一行＝待回礼＋待回总额（结论先行），第二行＝第一
  待回人（姓名＋其待回额，维持现状内容）。

**语义一致（金额双色进组件）**
- WPalette 新增 moneyGiven 镜像（黛青 浅 #14665A / 夜 #4FB3A6），
  收向用既有 primary（朱砂，与默认主题强调令牌一致）——与 App
  v5.0.2 MoneyTone 定值逐一对齐（五主题对比度实测在 V502-NOTES）。
- 组件进程读不到 App 的五主题设置（扩展进程 UserDefaults 不通，
  v4.4 已实证），恒走默认主题这一对，与 WPalette 既有镜像口径一致；
  深色模式走 dyn 动态色自动切换。
- 待回金额的符号口径说明：App 内 LedgerMath 定版是「逐笔走
  signedMoney、汇总走 fmtMoney」；组件里的逐人待回额是「逐笔」
  性质（某一个人欠的一笔账），按收向呈现 +¥；总额仍是汇总，
  保持 fmtMoney 无符号。本月收/送是两笔方向明确的流量数，按
  v5.1 任务定版带符号＋双色。

**深链分层（新增一条，沿用既有通道）**
- Core 新增 LiqianDeepLink.pendingURL()/isPending（liqian://pending），
  App 侧 onOpenURL 承接：切往来 Tab（待回礼汇总在该页），与长按快捷
  菜单「查看待回礼」同落点、同隐私锁守卫（锁着不承接）。
- 整卡 widgetURL＝pending；逐人行 Link＝person；记一笔＝AppIntent。
  三层落点各归其位（HIG：deep link to the right location）。
- 新增 3 个 Core 单测覆盖 pending 深链（圆环往返/排斥其他深链/
  不被 person、blessing 解析误吞）。

**占位与空态（全部设计过）**
- placeholder(in:) 改返专用占位条目（isPlaceholder），视图渲染
  WidgetSkeletonView 骨架屏（大数块＋两行灰块，.redacted），系统
  加载/重签过渡期不再空白。
- 无待回：结论式空态——小尺寸「暂无人情待回 · 收送都对上了」＋
  本月收一行支撑数；中尺寸右列改摆本月收/送；大尺寸名单区直说
  「暂无人情待回，账都清了」。不留空、不编数。
- 无下一场：日历图标＋「还没有重要日子」＋一句说明（倒计时小）；
  大尺寸下一场条显示「近期没有重要日子」。
- 无快照（App Group 未通/App 没写过）：「打开礼记」引导空态，
  沿用旧口径不冒充数据；组件库预览仍走带「示例」标的 demo 数据。

**刷新策略核查（通用项）**
- App 侧已有：WidgetSummaryWriter.write 写快照后即
  WidgetCenter.shared.reloadAllTimelines()；write 由 ContentView
  在 .task 与回前台（scenePhase active）时调用，即每次打开 App 都
  会刷新快照并要求组件重载——数据变更后回桌面即新数，这条链是
  通的，本版未改。
- 组件侧时间线政策沿用 .after(1 小时）：天数类数字（倒计时、
  下一场条）在视图里按「今天」现算，隔夜未刷新也不会显昨天的数；
  金额类靠 App 侧重载兜底。
- 新鲜度文案把快照 updatedAt 摆上卡面，是对这条链的诚实标注。

**锁屏隐私口径（维持现状，注明）**
- 金额出现位置仍只在：桌面三尺寸（privacySensitive）与锁屏矩形
  两行内（privacySensitive），圆形不放金额——与现状一致。
- 本版版式调整：矩形第一行由「N 人」改为待回总额（金额仍挂
  .privacySensitive()，锁定/遮蔽时系统打码，机制与现状相同）；
  第二行内容与现状完全一致（第一待回人姓名＋金额）。

**Live Activity**：未动源码，仅核查不回归——CI 编译与既有测试覆盖
其编译面，真机行为待验项沿用 V42 口径。

**版本与基线**：App/Widget Info.plist 字面量 5.1.0/53（Project.swift
工程设置同步），Share 休眠 target 保持 4.6.0 不动（不进包，恢复时
再同步，沿用 v4.7 口径）；不带 Share 扩展、CI 预签断言沿用。

## 五、真机待验（未验，不宣称）

1. 五种组件逐个加到桌面/锁屏：小（待回）、小（重要日子）、中、大、
   锁屏圆、锁屏矩——看层级与密度是否对版，大数有没有被长金额挤变形。
2. 点人直达：中/大名单行、小尺寸第一待回人行、锁屏两款，点按是否
   落到对应人物页；整卡空白处点按是否落往来 Tab 待回区。
3. 大尺寸「记一笔」按钮：点按是否唤起 App 并弹记一笔表单（真意图）。
4. 数据变更后刷新：在 App 里记一笔/改一笔，回桌面看组件数字是否
   跟上、新鲜度时间是否更新。
5. 空态：把待回清零（或用无待回的数据）看三尺寸空态；无重要日子
   时看倒计时小与大尺寸下一场条。
6. 锁屏隐私：锁屏未解锁状态下矩形组件金额是否被系统打码；圆形
   环形进度与人数是否对得上 App 内口径（待回人数/全部往来人数）。
7. 深色模式与默认主题下双色观感；旧快照兼容（先装 v5.0.2 写快照、
   再覆盖装 v5.1，未打开 App 前圆形应为无环降级版式、不崩）。
8. Live Activity 不回归：现场模式开启后锁屏横幅/灵动岛照旧。
