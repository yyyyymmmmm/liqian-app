# V4.3 回礼建议区间模型 — 落实记录（分支 feat/reply，未提交）

## 做了什么

把旧版「锚 ×1.2 取整」的糙区间换成可解释四步模型，全部计算在 LiqianCore，
界面只展示。模型依据品类已验证的祈灵/随礼记账簿规则（锚金额×年涨幅＋场合
系数＋吉利取整＋丧事单数）。

### Core 新文件 `Sources/LiqianCore/ReplyAdvice.swift`

- 入口 `ReplyAdvisor.advice(from:person:occasionType:today:annualRatePercent:)`
  → `ReplyAdvice?`（区间下限/上限/建议值/理由条目/锚素材/isBai）。
- **锚**：此人最近一笔收礼（日期最大，同日按传入新→旧序取先出现者，
  与旧版口径一致）。回退序（`pickAnchor` 纯函数）：
  最近一笔（日期合法者）→ 历史最大 → 历史中位。
  现行数据模型下日期由表单保证、金额恒 > 0，后两档是防御性兜底
  （日期损坏时仍能给参考），命中时理由如实写明来源，不假装最近一笔。
  无任何收礼记录 → nil，没依据不瞎给。
- **年涨幅**：复利 (1+rate)^距今整年数（年份差，与全 App 口径一致）；
  年率读设置键 `replyAnnualRatePercent`（0/3/5，默认 3）。
- **场合系数**（写死 `coefficient(for:)`，依据通行份量）：
  婚礼/寿宴/开业 1.0；乔迁/升学 0.9；满月/周岁 0.8；
  白事不走系数（奠仪按对等单数不打折）；未知/自定义事由 1.0。
- **取整**：
  - 红事优先整百：建议值＝折算向上取整到百，区间＝[向下整百, 建议值]，
    锚恰整百时区间上延一档留「略添」空间（500 → [500, 600] 填 500）；
    折算不足百元整百过头，改尾 6/8 吉数档（50 → [66, 88] 填 66）。
  - 白事取单数：整百加 1（500 → 501、450 → [401, 501]），
    不足百元取 101；理由固定带「各地习俗不同，以当地为准」。
- **理由条目**：锚来源（「上次他随你 ¥500（2023 年 · 婚礼）」）、
  涨幅折算（「过去 3 年，按年涨幅 3% 折算约 ¥546」，取整到元）、
  场合折算（「这次是满月，通常略轻于婚礼，已按八成折算」）、
  取整说明（红事「红事取整到 ¥600」/白事单数＋免责）。
  只给区间与事实，不下「应该随多少」的裁判。

### 旧函数处理：替换（非兼容保留）

`LedgerMath.returnGiftSuggestion` 与 `ReturnGiftSuggestion` 已删除，
原址留注释指向新模型；旧测试类 ReturnGiftSuggestionTests 随之删除

### 界面落地

- **人物详情「回礼参考」卡**：区间大字（¥500 – ¥600）＋「可参考 ¥600」
  ＋理由逐行（· 前缀、footnote 次级色）＋「只是按你和 X 的往来记录算的，
  仅供参考，量力而行」。本页无具体场合，场合系数取锚所属事由。
  无收礼记录时卡片不消失，出回退文案（还没收过他的礼…按当地通常
  份量拿捏），不再像旧版整卡隐藏。
- **记一笔（随礼）**：金额 chips 下方一行小字提示
  「回礼参考 ¥500–¥600（上次他随你 ¥500），点按填 ¥600」，
  点按把建议值填进金额框。仅新建＋随礼方向＋已填姓名＋有依据时出现；
  场合＝当前礼簿事由（从人物入口记账时随所选礼簿变）。
- **设置**：「我的 → 记录」加「回礼参考年涨幅」菜单行（不折算/3%/年/5%/年），
  与两处消费方同键（`ReplyAdvisor.annualRateKey`）同源。
