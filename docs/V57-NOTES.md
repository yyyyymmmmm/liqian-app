# v5.7 问账双修：账外问题永不沉默＋键盘收起三件套

分支 `feat/v57-advisor-manners`（基线 feat/v56-voice-panel），版本 5.7.0/65。
用户真机点名（附截图）：问账里问「郭坤随了多钱」正常出卡，接着问
「明天天气咋样」——没有任何回复、消息挂在那里；随后又发现问账页
键盘收不回去。用户定的政策原话：「这是AI呀，答案基于软件数据，
但是没有的问题要自己学会回答呀」。

## 一、沉默根因定位（逐出口查实，不猜）

拿「明天天气咋样」在旧代码里逐段走查（AdvisorView.ask →
answerWithTools → resolveIntent → AdvisorRules → 末端落点）：

1. **工具主路径没有「回答账外问题」的出口**：工具问答系统提示词
   旧第 6 条原文是「只处理与人情账目有关的事（查账与记账）；无关
   问题礼貌说明自己只管人情账目」——模型即便第一轮就出文字，也只
   被允许给一句拒绝语；这不是答复，是设计性拒绝。
2. **空 content 不是被某一行吞掉，而是整链没有接住**：chatTurn 对
   空 content 的处理是抛 badResponse（DeepSeek.swift，口径明确），
   answerWithTools catch 后返回 nil 落降级——行为本身没错，错在
   降级链的终点同样答不了（见第 4 条）。
3. **工具循环会把时延拉到「像沉默」**：「明天」是时间词，按提示词
   第 2 条的时间换算纪律，模型容易去调 upcoming_events /
   query_records 拿明天当条件查，轮数上限 4 轮；再加降级意图解析
   1 次，共最坏 5 次串行网络往返才落地。期间用户只看得到过程状态
   行——在截图里的农村 4G 环境下，这就是「消息挂着没回复」。
   （轮数是代码上限推得的最坏界；模型当轮实际调没调工具，本机无
   调用日志可查，不冒充实测。）
4. **降级链的唯一终点是非答复**：意图提示词对账外问题按定义只能
   输出 unknown → resolveIntent 不返回 → AdvisorRules 四级关键词
   （人名/待回/事由/时段）对「明天天气咋样」全部落空 → nil →
   ask 旧末端落 .result(.unsupported)，上屏文案是「这个问法我还
   不会，去往来页搜人名也可以。」——问天气，得到的是「我不会这
   个问法」，等于没回。
5. **排除项**：全链不存在死循环或丢消息的代码路径——工具循环有
   4 轮硬上限、网络请求有 30 秒超时、ask 的每条分支旧代码最终都
   会 append 一条消息。所以「零回复」的实因是三件叠加：提示词封
   死账外作答（设计性拒绝）＋最坏 5 次串行往返的长时延（席上沉
   默）＋终点是非答复卡。本版三处一起修。

## 二、修一：回答政策——账外 lane＋永不沉默

### 工具提示词第 6 条（替换，1–5 条与 draft_record 段落逐字未动）

旧：「只处理与人情账目有关的事（查账与记账）；无关问题礼貌说明
自己只管人情账目。」

新（账外 lane）：「账外问题（与人情账目无关的问题，如天气、常
识、礼仪人情、闲聊、问这个 App 怎么用）：不要调任何查账工具，
直接用你自己的知识简洁作答；不许说『我只管账目』把用户推开，
也不许假装查过账。一句问题里账内账外都有时，账内部分按上面
1-5 条先查工具，账外部分在同一条回复里用自己的知识答。账外回
答里不许出现编造的账目金额、人名和记录；被问到这个 App 怎么
用时，只介绍它确实有的功能：记人情账、问账查账、待回提醒、
礼谱与报表导出、语音和拍照记账，没有的功能不要许诺。需要实
时信息才能答准的（实时天气、新闻、价格行情），先明说你拿不到
实时数据，再给常识性的回答或建议，不许编一个具体的实时数值，
也不许只说『查不到』就结束。」

效果：账外问题在工具主路径第一轮就以纯文字直答（一句话里混合
账内账外时先查工具再同条作答）；账内纪律（铁律 1–5：金额只许
来自工具、查不到明说、draft_record 只起草待确认）一字未动。

### 管线末端通用作答 lane（工具路径与意图管线都兜不住时）

新增 answerGenerally：无工具纯文本对话（DeepSeekClient.chatText），
专用 generalSystemPrompt 与工具提示词的 lane 同口径（自身知识
作答/实时信息先声明拿不到再给常识/不编账目数据/不许诺没有的
功能）。任何失败（网络/接口/空回复）返回 nil，不自己吞编。

### 兜底收敛（硬保证，LiqianCore/AdvisorReply.swift）

```
提问
└─ 工具问答（≤4 轮；账内调工具、账外 lane 第一轮直答）
   ├─ 成功 → .answer（结论文字＋同源卡片）            [原有]
   └─ nil（异常/空回复/轮数耗尽）
      └─ 意图解析＋规则兜底 → AdvisorEngine 结果卡     [原有]
         └─ 兜不住（unknown＋规则 nil）
            └─ 通用作答 lane（仅 AI 就绪时调用）
               └─ AdvisorReplyConvergence.resolve 裁决：
                  ├─ 拿到非空回答 → .answer（纯文字）  [账外正常作答]
                  ├─ AI 未就绪     → .result(.unsupported) [原有卡，带开通引导]
                  └─ AI 就绪但全链失败 → .note（致歉文案） [真故障才致歉]
```

出口全表（任务书点名的每个出口）：模型空文本 → chatTurn 抛错 →
主路径 nil → 走收敛段；无工具无文本 → 同上；循环到上限 → nil →
走收敛段；降级管线无结果 → 通用 lane；网络异常 → 通用 lane 亦
失败 → .failureApology 致歉 note（文案单点在
AdvisorReplyConvergence.failureApologyText：点明可能是网络问题、
请稍后再问，不是终结性拒绝）。收敛裁决是纯函数，7 个单测覆盖
（AdvisorReplyTests：通用回答胜出/文本修整/就绪无答落致歉/空白
等同没拿到/未就绪落 unsupported/防御性有答出答/致歉文案可行动）。

**账内纪律未松动**：涉及金额/人数/日期的断言仍只许来自工具
（铁律 1–5 与意图解码「结构里不声明金额字段」均未动）；账外两
条提示词都明文禁止编造账目数据与虚构 App 功能。

## 三、修二：键盘收起三件套（仅问账页）

公共锚：新增 `@FocusState composerFocused`，输入坞 TextField 绑
`.focused($composerFocused)`；三件套都经放掉这一位收键盘，输入
坞既有布局与语音面板接线零改动。

1. **滚动收键盘**：消息 ScrollView 加
   `.scrollDismissesKeyboard(.interactively)`——滑动消息流键盘跟
   手收起。
2. **点空白收键盘**：消息 ScrollView 加
   `.simultaneousGesture(TapGesture().onEnded { composerFocused = false })`
   ——点消息区任意处即收；simultaneous 不抢占，卡片按钮（进人物
   详情/确认入账等）动作照常触发，滚动拖动不触发 TapGesture。
3. **收起钮**：`.toolbar` 加 `ToolbarItemGroup(placement: .keyboard)`，
   右侧 chevron.down 按钮（无障碍标签「收起键盘」），只在键盘升
   起时出现在键盘附件栏，不占输入坞位置。

**其他页面同类结构清单（本轮不扩散，仅记录）**：

- 一句话记账（QuickSentenceView）：Form 内多行 TextField＋解析
  钮的「一句话输入」入口，非聊天流；无 FocusState 绑定、无三件
  套（Form 有系统表单滚动行为，但点空白/附件栏收起未配）。
- 贺词（GreetingView）：表单＋生成结果；已有
  scrollDismissesKeyboard(.interactively) 一项（本页早先就有），
  缺 FocusState 点空白收起与键盘附件栏收起钮。
- 其余带 TextField 的页面（RecordFormView/BatchEntryView/
  SceneModeView 等）是结构化表单、各有自己的 FocusState 纪律，
  不属聊天输入结构，不列入本清单。

## 六、真机待验（装 v5.7 后）

1. 问「明天天气咋样」：有一条像样回复——明说拿不到实时天气＋给
   常识性建议，不再是沉默或「我只管账目」；
2. 问常识/礼仪问题（如「同事结婚随多少合适」）：能直接答（涉
   具体账目数字时仍应走工具核对，不许凭空报账上数字）；
3. 账内问题照旧：出卡、数字与账一致（工具纪律未动）；
4. 断网后提问：最终落一条致歉兜底回复（可能要等链路超时，不
   是无限挂着），恢复网络后正常；
5. 键盘三路：滑动消息流收键盘、点消息区空白收键盘、键盘附件
   栏 chevron.down 收起钮收键盘；点卡片按钮动作不受影响。
