# v5.2.1 AI 设置页重做＋验证状态修复

## 一、功能根因（用户截图实锤，代码查实）

截图现象：Key 已保存（尾号 51af），「验证状态」却显示**未验证**，
而页脚写着「保存时会自动验证一次」「开关打开且 Key 验证通过，AI
功能才可用」——三处自相矛盾。逐项查实：

1. **验证状态只活在内存**：旧 `AISettingsView.verifyState` 是纯
   `@State`，保存时确实会探活并置 `.verified`，但视图一重建（离开
   再进页面）必然重置 `.unverified`，验证结论从未落盘。所以用户
   每次打开这页都看到「未验证」，与是否真验过无关。
2. **门控口径与文案不符（文案错、实现对）**：`AIAccess.readiness()`
   实际只查两件事——钥匙串里有 Key、`aiEnabled` 开关打开——**根本
   不查验证状态**。页脚「验证通过才可用」是假口径；本次按「已保存
   ＋开关开即可用、验证只作健康提示」定版，文案与实现对齐，避免
   验证接口抽风把整个管家锁死。
3. **开关蓝色**：旧代码已写 `.tint(Palette.primary)`，截图中的蓝
   与腾讯蓝主题强调令牌 `#0052D9` 几乎同色、肉眼与 iOS 默认蓝
   无从分辨；本次重做后开关继续由主题强调令牌染色（构造上保证），
   真机待验时请在朱砂默认主题下复核应为朱砂色。
4. 其余 low 点：字阶松散（LabeledContent 大字平铺）、「更换 API Key」
   是普通按钮文案与输入框分离、灰字观感像禁用、删除无确认、说明段
   是整段旧文案（含已与 v5.2 现状不符的「发送前界面会写清楚要发
   什么」）。

## 二、修复（验证闭环）

- 新增 `Sources/LiqianCore/AIVerification.swift`：验证记录落盘
  （结论＋时间＋Key 尾号指纹＋失败人话原因，存 UserDefaults，
  只存结论不存 Key）；状态由「记录＋当前 Key 尾号」派生：尾号
  对不上（换过 Key）自动回未验证；删 Key 时记录一并清。
- 页面四态齐全：未验证／验证中／已验证（带时间）／验证失败
  （带原因行），以状态丸呈现（色点＋短文案）。
- 「验证一次／重新验证」按钮：有 Key 且未处于已验证时出现，
  点按发一次极小接口调用（与保存时探活同一口径）。
- 保存流改为「保存并验证」主按钮（玻璃主钮＋主题染色）：存
  钥匙串→自动打开开关→立即探活→结论落盘。空输入时禁用，页脚
  写明操作路径，不再有灰字假禁用观感。
- 失败原因分档人话化：401/403 Key 被拒绝、402 余额不足、429
  频繁、其余 HTTP 异常带码、网络失败、返回异常——不许静默。
- 删除 Key 补 confirmationDialog 确认弹窗；删除连带清验证记录
  并关开关（与旧行为一致）。

## 三、设计重做

- 标题「AI 智能助手」→「**AI 管家**」（去空话词「智能」，与
  「我的」页分组名/入口名统一；MeView 入口行、DeepSeek 引导
  文案、AdvisorView、LibuExportView 的路径引用同步改名）。
  **例外**：`Legal.swift` 隐私政策正文为用户定稿，内有「我的 →
  AI 智能助手」旧称，本次未擅动定稿，待用户确认后另行修订。
- 排版回正常字阶：标签正文字号、值 subheadline 次色、行高走
  LiqianMetrics；分组卡面与页底走主题令牌（pageBG/surface 口径
  与「我的」页一致）。
- 开关 `.tint(Palette.primary)` 主题强调令牌染色。
- 说明段落精简为三条要点（钥匙串存储／直连官方接口＋问账只发
  问题与工具结果子集／金额本地计算），逐句按 v5.2 现状核写。

## 六、真机待验（未宣称已验）

1. 存量 Key 打开页面：若该 Key 此前从未在本版验过，显示「未验证」
   ＋验证一次按钮，点一次应变「已验证 · 时间」；杀掉 App 重进，
   状态应保持已验证（落盘生效的判据）。
2. 换 Key 全流程：输入新 Key→保存并验证→状态按新 Key 重新验证；
   故意填错 Key→应显示验证失败＋「Key 被拒绝」原因行，重新打开
   页面失败状态仍在。
3. 开关染色：默认朱砂主题下开关为朱砂色；切腾讯蓝主题应随之变蓝。
4. 删除 Key：弹确认框；确认后 Key 行与状态区消失、开关自动关闭，
   管家入口应给出「还没填 Key」引导。
5. 门控口径：Key 已保存但未验证时，管家应可正常提问（验证只作
   健康提示、不拦截）。
