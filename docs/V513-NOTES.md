## 二、语言股（482cd6a）

### 机制
- 偏好三档（跟随系统／简体／繁體），存 UserDefaults 键 `appLanguagePreference`，
  解析单点收敛 Core `AppLanguage`：显式档直接定；跟随系统只认系统首选语言
  （含 Hant 字系或地区 TW/HK/MO 判繁，其余——含非中文——回落简体）。
- 即时生效两路：根视图（LiqianApp）按解析值设环境 locale（系统控件、日期格式
  随之切换，修订 v2.4 固定 zh_CN）；ContentView 根身份键拼入语言档，切换即重挂
  子树，代码拼装串（L10n）与字面量一并换档，不重启。
- 界面文案：SwiftUI 字面量由系统按 locale 查 `Localizable` 表；代码拼装串走
  `L10n.string/format`（App 层，按解析语言取对应 .lproj；缺条目回退键本身＝
  简体原文，不丢字）。简体档不建表——缺表即显示简体原文，与旧版一致。

## 四、字号股（e5273a2）

- 三档（标准／大／特大），存 UserDefaults 键 `appTextSizeTier`，外观页语言节
  下方新设字号节。
- 机制：档位只设保底、不封顶不压低——Core `TextSizeScale.targetIndex` 取
  max(系统下标， 档位保底）：标准＝无保底（完全跟随系统）；大＝至少 xxLarge；
  特大＝至少 accessibility1（封在辅助功能一档，是不撑爆主要布局的克制上限）。
  系统字号本来更大时尊重系统。
- 接线：ContentView 读系统 dynamicTypeSize＋档位算出生效值，根修饰链
  `.dynamicTypeSize(...)` 注入，即时生效。主要界面为语义字体（TextStyle），
  缩放成立；已有的 dynamicTypeSize 适配点（ChartsView 网格列数、
  LedgerDetailView 行数）随注入值自动跟随。
- 不跟随：礼谱 PDF 全系、印刷参数页、分享图卡——静态成品、版式定版字号；
  BatchEntryView「大字模式」是现场场景的独立固定字号开关，口径不变、与
  本档位互不干涉。

## 五、存量口径变化（如实记录）

1. 谱面语言：v2.8 定版「礼谱恒繁体」被 v5.13 用户定版修订为「跟随 App 语言」。
   老用户未动设置时：偏好＝跟随系统，系统为简体中文者谱面将变简体——这是
   定版变化的应然结果，非回归。
2. 示例身份：去掉标题认领后，**旧版本生成且从未写入存储 ID 的示例**（更早期
   按标题生成的存量）将不再被识别为示例——其数据会开始计入统计，且「清除
   示例数据」清不掉它（用户可在最近删除/礼簿管理里手动删）。现行版本生成的
   示例都写有 ID，不受影响。
3. UserDefaults 不进备份的既有风险不变：换机恢复后存储 ID 丢失，示例将
   脱钩为真实数据（诊断报告相邻风险 2，概率低、记录在案，本版未处理）。
4. CSV 表头维持简体原字（机器格式兼容优先），繁体档下导出 CSV 表头仍为
   简体——属有意口径，非漏翻。

## 六、已知边界

- 界面繁体覆盖：无插值固定字面量全覆盖；**含插值的拼装句**（如「共 N 笔」
  类动态句，约 139 处抽取点）本版未进本地化表，繁体档下这类句子仍显简体
  原文（不丢字）。后续按 L10n.format 路线逐条迁移。
- 小组件（Widget）不跟随 App 内语言与字号档：走系统语言/系统字号（组件
  读不到 App 偏好，与主题既有边界同理）。
- 字号特大档下个别密集排版（图表网格、排行行）靠既有 dynamicTypeSize
  适配点与自然换行承接，未逐页做 AX 级布局改造；真机观感待验。
- 法务文本（隐私政策/用户协议正文，Legal.swift）是代码内长文常量、不走
  SwiftUI 字面量查表路径，繁体档下仍显简体原文——法律文本的繁体版需
  法务口径另行定稿，不在本版机校范围。
